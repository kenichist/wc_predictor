# World Cup Predictor Data Pipeline

This repository builds a clean, reproducible match-level dataset for training future FIFA World Cup 2026 match outcome models. It is a data engineering pipeline, not a model training project.

## Data Sources

- Historical international results: `martj42/international_results`
- Recent matches: `football-data.org` API, using `FOOTBALL_DATA_TOKEN`
- World Cup 2026 fixtures/results backup: `openfootball/worldcup.json`
- Optional future player/squad statistics: modular `soccerdata` stubs that do not affect the core pipeline

## Setup

python -m venv .venv

## Feature Correctness

Rolling team-form features are generated by processing matches chronologically. For each match, the pipeline calculates team history from matches before that match date, then updates team history only after all matches from that date have received features. This prevents the current match or same-day matches from leaking into the features.

The simple Elo implementation follows the same rule and emits pre-match ratings before applying match updates.

## Match Weights

`match_weight` combines exponential recency decay with tournament importance. Defaults are configured in `configs/sources.yaml` and can be adjusted without changing code.

## FIFA Rankings

If `data/external/fifa_rankings.csv` exists, the feature builder joins the latest available ranking before each match date. Rows on the same date as the match are not used. Expected columns:

- `date`
- `team`
- `rank`
- `points`

If the file is absent or malformed, ranking columns are created as nulls and the pipeline continues.

### Method Notes

The SOTA-style layer predicts individual matches probabilistically, then runs Monte Carlo tournament simulations. This is preferable to a direct "winner classifier" because the World Cup winner depends on group results, goal difference, knockout paths, and match-level uncertainty.

Ablation uses time-aware splits:

- train: before `2022-01-01`
- validation: `2022-01-01` to `2024-12-31`
- test: `2025-01-01` onward

Champion probabilities are simulation frequencies, not guarantees. A team at 18% should be interpreted as winning roughly 18 out of 100 comparable simulated tournaments under the current model assumptions.

## Adding FIFA Rankings and World Football Elo

FIFA rankings and World Football Elo provide external team-strength signals. They help avoid overly flat match probabilities by giving the model independent estimates of team quality beyond recent form and the internal Elo implementation.

The advanced feature layer works without these files, but the `fifa_rankings` and `external_elo` groups stay null until real data is added. Templates are examples only and should not be used as final model inputs.

Put files here:

```text
data/external/fifa_rankings.csv
data/external/world_football_elo.csv
```

Required FIFA rankings schema:

```text
date,team,rank,points
```

Required World Football Elo schema:

```text
date,team,elo
```

Create templates:

```bash
python -m src.cli prepare-external-templates
```

Prepare manually downloaded raw files:

```bash
python -m src.cli prepare-fifa-rankings --input path/to/raw_fifa_rankings.csv
python -m src.cli prepare-world-football-elo --input path/to/raw_world_football_elo.csv
```

Validate external files:

```bash
python -m src.cli validate-external-data
```

Rebuild advanced features:

```bash
python -m src.cli build-advanced-features
```

Check feature null rates:

```bash
python -m src.cli feature-null-report
```

Expected activation:

- `fifa_rankings` `average_null_rate < 1.0`
- `external_elo` `average_null_rate < 1.0`
- both groups have `usable_columns > 0`

Rerun ablation:

```bash
python -m src.cli run-ablation
```

## Historical FIFA/Elo Snapshot Import

Current FIFA rankings and World Football Elo snapshots help the current World Cup prediction input, but historical snapshots are required for training and ablation because old matches cannot safely use future rankings. The pipeline uses strict as-of joins, so rows on or after the match date are not used for that match.

Put FIFA snapshot files here:

```text
data/external/fifa_rankings_snapshots/
```

Put World Football Elo snapshot files here:

```text
data/external/world_football_elo_snapshots/
```

Use filenames with dates when the file does not already include a date column:

```text
fifa_YYYY-MM-DD.csv
elo_YYYY-MM-DD.csv
```

Supported formats:

- CSV
- TXT
- Markdown table
- HTML table
- Excel xlsx

Required columns:

- FIFA: `rank`, `team`, `points`
- World Football Elo: `team`, `elo`

Common aliases are accepted, including `country`, `nation`, `position`, `pos`, `pts`, `rating`, `score`, and `total_points`.

Run the combined historical import and rebuild:

```bash
python -m src.cli import-historical-rating-snapshots --rebuild
```

You can also import one source at a time:

```bash
python -m src.cli import-fifa-ranking-snapshots --input-dir data/external/fifa_rankings_snapshots --output data/external/fifa_rankings.csv
python -m src.cli import-world-football-elo-snapshots --input-dir data/external/world_football_elo_snapshots --output data/external/world_football_elo.csv
```

Then inspect:

```text
data/reports/historical_rating_coverage_report.md
data/reports/feature_null_rate_report.md
data/experiments/ablation_results.csv
```

Do not use future rankings for historical matches. Add dated historical releases before the validation period if you want FIFA/Elo ablation to become meaningful.

Split prediction outputs so placeholder fixture rows are not mixed with real team-vs-team rows:

```bash
python -m src.cli split-prediction-outputs
```

Run the full advanced pipeline:

```bash
python -m src.cli full-sota-pipeline --model catboost --feature-set full_football_only --n-sims 100000
```

If these feature groups remain null, ablation results will not improve. Add real `data/external/fifa_rankings.csv` and `data/external/world_football_elo.csv` first, then rerun validation, advanced features, null reporting, and ablation. The simulator resolves actual knockout teams before predicting matchups and does not use placeholder rows such as `1A`, `3C/E/F/H/I`, or `W101` for knockout simulation.

## Acquiring Real FIFA Rankings and World Football Elo

The external rating feature groups require real files:

```text
data/external/fifa_rankings.csv
data/external/world_football_elo.csv
```

Templates are not real data. They are examples for schema only.

URL mode uses `configs/sources.yaml` or a command-line override:

```bash
python -m src.cli acquire-external-ratings
python -m src.cli acquire-fifa-rankings --url https://example.com/real_fifa_rankings.csv
python -m src.cli acquire-world-football-elo --url https://example.com/real_world_football_elo.csv
```

Local file mode accepts CSV, Excel, JSON, and HTML tables:

```bash
python -m src.cli acquire-fifa-rankings --input path/to/fifa_file.csv
python -m src.cli acquire-world-football-elo --input path/to/elo_file.csv
```

The acquisition commands normalize common source columns such as `country`, `nation`, `position`, `total_points`, `rating`, and `rating_date`. They save raw copies under `data/raw/`, write validated outputs under `data/external/`, and preserve existing valid files if a new acquisition fails.

Validate and rebuild after adding real data:

```bash
python -m src.cli validate-external-data
python -m src.cli build-advanced-features
python -m src.cli feature-null-report
python -m src.cli run-ablation
python -m src.cli full-sota-pipeline --model catboost --feature-set full_football_only --n-sims 100000
```

Confirm activation in:

```text
data/reports/feature_null_rate_report.md
data/reports/external_rating_activation_report.md
data/experiments/ablation_results.csv
```

Expected activation:

- `fifa_rankings` average null rate is below `1.0`
- `external_elo` average null rate is below `1.0`
- both groups have usable columns above `0`
- ablation no longer reports the FIFA/Elo feature sets as identical solely because columns are null

If automatic acquisition cannot run because no URL is configured, the command prints the exact file path and schema to provide. The model should not be treated as SOTA until these reports show the external rating groups are active and ablation is no longer blocked by null columns.
